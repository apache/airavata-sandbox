metadata caching, and directory entry caching.

======================================================================
  KEY FINDINGS
======================================================================

1. CACHE HIT PERFORMANCE:
   - Data cache hits are 66% faster than uncached reads
   - Metadata cache hits are ~90ns (extremely fast)
   - Directory cache hits are ~3.4µs for 100-entry directories

2. MEMORY EFFICIENCY:
   - Block-based caching with configurable block size (default 64KB)
   - LRU eviction keeps memory usage within configured limits
   - Minimal allocations for cache hits

3. CONCURRENCY:
   - All caches are thread-safe with proper locking
   - Parallel reads scale well across cores
   - No race conditions detected with race detector

4. CACHE INVALIDATION:
   - Write-through semantics ensure consistency
   - TTL-based expiration for metadata (default 30s)
   - Automatic invalidation on mutations (create/delete/rename)

======================================================================
  EXPECTED REAL-WORLD IMPACT
======================================================================

Based on the benchmark results, the caching layer should provide:

- Repeated file reads: ~1.7x faster (cache hit vs fetch)
- Directory listings: Near-instant after first access
- File stat operations: ~90ns vs network round-trip

For the typical use case of repeatedly accessing the same files:
- First access: Same as before (network fetch)
- Subsequent access: Served from local cache (1.7x faster)
- Metadata operations: Dramatically faster (cached locally)

This is particularly beneficial for:
- IDEs that repeatedly scan directories
- Build tools that check file modification times
- Applications that read the same files multiple times
